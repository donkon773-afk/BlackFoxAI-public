# BLACKFOX AI WORKSTATION — руководство (v3.1)

Рабочая платформа для кластера LLM-узлов: один хаб, любое число
OpenAI-совместимых inference-серверов (LM Studio, llama.cpp, Ollama, vLLM).
Направление работы задаётся промпт-ролями узлов и skills — платформа
не привязана ни к какой предметной области.

Подробная справка с рекомендациями по настройке встроена в интерфейс:
вкладка **📖 Справка**.

## Запуск

Хаб (на главной машине) — ярлык **BlackFox Hub** на рабочем
столе (создаётся `make_shortcut.ps1`) или `launch_hub.bat`: он поднимает
сервер **отдельным процессом** (переживает закрытие окна), пишет вывод в
`data\hub.log` и открывает интерфейс по той схеме, которая включена в настройках
(https при включённом TLS).

Вручную, с выводом в текущее окно:

```
python -u hub_server.py 8765
```

Чтобы хаб поднимался сам при входе в систему:

```powershell
.\autostart_hub.ps1 -Install    # включить (задача планировщика, без окна)
.\autostart_hub.ps1 -Status     # проверить
.\autostart_hub.ps1 -Remove     # выключить
```

Агент на каждом удалённом узле (MacBook, ноутбук) — одной командой
**на самой машине узла**; хаб раздаёт установщик со своим адресом внутри:

Установщик содержит **секрет кластера**, поэтому хаб отдаёт его только
администратору (машина-админ или вход под паролем администратора) либо по
**одноразовому ключу установки**. Ключ выпускается кнопкой «📡 Установить
агент» в карточке узла (Телеметрия или Настройки → Узлы): хаб создаёт ключ на
30 минут и показывает готовую команду с ним. Общий вид:

```powershell
$h=@{'X-Install-Token'='<ключ>'}; irm -Headers $h "https://<хаб>:8765/install-agent.ps1?port=8766" | iex
```

```bash
curl -fsSL -H "X-Install-Token: <ключ>" "https://<хаб>:8765/install-agent.sh?port=8766" | sh
```

Ключ гаснет после установки (или по истечении срока); запрос без ключа
получает 403 и попадает в журнал безопасности. Если заголовок передать
неудобно, ключ принимается и как параметр `?t=<ключ>`.

Если у хаба **самоподписанный** сертификат, интерфейс добавляет в команду
проверку открытого ключа (`--pinnedpubkey`), и загрузка идёт встроенным
`curl.exe` — так проверка надёжнее, чем колбэк PowerShell. С сертификатом
Tailscale (Let's Encrypt) пиннинг не нужен и не добавляется: сертификат
проверяется обычным способом, как у любого сайта.

Установщик скачивает `node_agent.py` с хаба, находит Python, включает
автозапуск (ярлык в Startup / launchd / systemd --user), пытается открыть
порт в брандмауэре и сразу поднимает агент. Готовые команды с подставленным
адресом показаны в карточке узла на вкладке Телеметрия и по кнопке
«📡 Установить агент» в Настройки → Узлы.

Вручную, без автозапуска:

```
python3 node_agent.py 8766            # без токена, доступ только из Tailscale/LAN
python3 node_agent.py 8766 --token S  # с токеном (укажите его в Настройки → Подключение)
```

Интерфейс: `https://<hub-host>:8765` — открывать нужно
**по имени Tailscale**: сертификат выписан на него, а по IP
или `127.0.0.1` браузер сообщит о несовпадении имени. Имя хаба задаётся в
Настройки → Подключение (`tunnel_host`) и подставляется во все команды.

Схема — `https`, если включён TLS (Настройки → 🔒 Безопасность), иначе `http`;
при включённом TLS обычный `http` на этом порту не обслуживается.

### Сертификат

`tailscale cert` выдаёт настоящий сертификат Let's Encrypt на имя узла в
тейлнете (требуется включённый HTTPS в <https://login.tailscale.com/admin/dns>).
Кнопка ① в Настройки → 🔒 Безопасность делает это из интерфейса. Сертификат
живёт ~3 месяца; хаб раз в 12 часов сам просит Tailscale продлить его и
перечитывает файлы без перезапуска (события `tls_renewed` в журнале).
Запасной вариант без Tailscale — самоподписанный сертификат (кнопка ②):
канал шифруется так же, но браузер предупредит о доверии, пока сертификат не
добавлен в доверенные на устройстве.

## Телефон и планшет

Отдельной мобильной версии нет: интерфейс один и перестраивается под ширину
экрана (порог — 760 px, плюс телефон в альбомной ориентации). Все функции
десктопа доступны с телефона; контролы композера не дублируются, а физически
переезжают в шторку, поэтому расхождений между версиями быть не может.

| Элемент | На телефоне |
|---|---|
| Вкладки | нижняя панель: Чат, Узлы, Роли, Модели, «Ещё» |
| Ветки чатов | шторка слева (кнопка ☰ или свайп от левого края) |
| Режим/узел/skill/параметры | чипы над полем ввода → шторка с теми же контролами |
| Панель узлов | горизонтальная лента, смена модели и пинг на месте |
| Промпт-роли | список → карточка с кнопкой «◀ К списку» |
| Настройки, справка | разделы лентой вкладок сверху |
| Обновление | потянуть вниз |

Дополнительно на телефоне: установка на домашний экран (PWA —
`web/manifest.webmanifest`, `web/sw.js`), голосовой ввод (кнопка 🎤),
блокировка засыпания экрана на время генерации, уведомление и вибрация по
готовности ответа в свёрнутом приложении, работа интерфейса без связи
(данные кластера при этом никогда не берутся из кэша).

Установка на домашний экран и уведомления требуют HTTPS без предупреждений —
то есть открывать нужно по имени Tailscale, на которое выписан сертификат.

Иконки приложения генерируются скриптом `make_icons.ps1` в `web/icons/`.

## Узлы (значения по умолчанию)

Хаб стартует с двумя **узлами-заглушками** — замените их адрес, модель и
роль в Настройки → Узлы или добавьте свои узлы мастером.

| Узел | Адрес | Роль | Телеметрия |
|---|---|---|---|
| `node_1` | 127.0.0.1:1234 | — | авто |
| `node_2` | 127.0.0.1:1235 | — | авто |

Мастер добавления проверяет адрес, читает список моделей, забирает железо
(локально или у агента), при необходимости спрашивает, какой GPU занимает
узел, и предлагает класс узла, роль из библиотеки, модели и параметры.

«Авто» означает: узел на машине хаба → локальная телеметрия, удалённый →
агент по адресу из endpoint + порт агента (8766).

## Режимы выполнения

| Режим | Что делает |
|---|---|
| 🎯 Один узел | запрос одному узлу с историей ветки |
| ⚡ Все узлы | параллельно на все включённые, ответ каждого отдельно |
| 🔄 Конвейер | шаги из настроек по очереди, контекст передаётся дальше |
| 🧩 Гибрид | свой план ветки: этапы по очереди, внутри этапа узлы параллельно |
| 🤝 Консилиум | черновики → обсуждение между узлами → **один** ответ модератора |

Режим, план, консилиум, skill и «без ролей» хранятся в самой ветке,
поэтому разные пользователи одновременно работают со своими схемами.

## Skills

`default`, `fast` (быстрый), `deep` (глубокое рассуждение), `web` (поиск в
интернете), `verify` (сверка фактов), `code`, `critic`, `brief`.
Skill добавляет инструкцию к промпту, переопределяет параметры генерации и
может включать поиск (хаб ищет через DuckDuckGo, читает страницы и передаёт
их узлу; в ответе — ссылки [n] и список источников). Свои skills создаются
в Настройки → Skills.

## Файлы в чате

Кнопка 📎, перетаскивание в композер или Ctrl+V прикладывают файлы к запросу.
Хаб сохраняет их в `data/files/` (индекс `index.json`) и извлекает текст
(`hub_files.py`, только stdlib):

| Формат | Как читается |
|---|---|
| текст/код (.txt .md .csv .json .py .ps1 …) | напрямую, кодировки utf-8 / cp1251 / cp866 |
| .docx / .xlsx / .pptx | zip + XML (абзацы / строки листов / слайды) |
| .pdf | `pdftotext`, если установлен; иначе грубый разбор потоков (сканы — нет) |
| изображения | как есть, только узлам с `vision: true` (Промпт-роли → узел) |

Лимиты в `settings.files`: `max_mb` 25, `per_file_chars` 40000, `total_chars`
120000, `history_chars` 6000 (в последующих ходах). API: `POST /api/files/upload
{name, data(base64), thread_id}` → `{file}`; `/api/files/list`, `/api/files/delete`,
`GET /api/files/get?id=`. В `/api/execute` — `files: [id, …]`.

## 🖥 Агент ПК — команды на узлах (администратор)

Модель может выполнять команды PowerShell / cmd / bash на узлах кластера.

1. Разрешить на узле: Промпт-роли → узел → «Агент ПК: разрешено»
   (`exec_enabled`, по умолчанию выключено). На самом узле выполнение можно
   запретить переменной `BLACKFOX_NO_SHELL=1`; агент принимает действие `shell`
   только по подписи HMAC.
2. В композере включить **🖥 Агент ПК** (только режим «Один узел», только
   администратор). Хаб добавляет модели системную инструкцию со списком
   разрешённых узлов и протоколом.
3. Протокол — текстовый, работает с любой моделью: блок
   ```run:powershell@<ключ_узла>` … ```` в ответе. Хаб показывает команду
   карточкой, ждёт подтверждения (`tools.approve = confirm`, либо `auto`),
   выполняет через `node_exec(key, "shell", …)`, возвращает stdout/stderr/код
   выхода следующим сообщением; до `tools.max_steps` (8) шагов.
4. Аудит: события `tool_exec`, `tool_denied` в `data/security.log`.

Ручное выполнение: `POST /api/tools/exec {node_key, command, shell, timeout}`;
подтверждение: `POST /api/tools/approve {call_id, approve}`. Агенты на других
машинах должны быть обновлены до версии с действием `shell` (переустановка
скриптом или приложение).

## Язык ответов

Настройки → LLM → «Отвечать на языке вопроса» (включено по умолчанию):
хаб определяет язык каждого сообщения и добавляет к системному промпту
правило отвечать строго на нём. Действует во всех режимах, включая «без
ролей» и консилиум.

## Вкладка «Модели»

Для каждого узла: железо, активная модель, список моделей с расчётом —
объём весов, KV-кэш при выбранном контексте, вердикт (помещается / впритык
/ выгрузка на CPU / не помещается), ожидаемая скорость tok/s и условная
«сила» модели. Матрица «что куда ставить» сравнивает все известные модели
со всеми узлами и указывает лучший узел. Администратору дополнительно:
загрузка/выгрузка моделей в память, точная оценка через `lms --estimate-only`,
удаление файлов, поиск на HuggingFace и скачивание на любой узел
(`lms get` для LM Studio или прямая ссылка на GGUF) с прогрессом.

## Вкладка «Админ» (только с хост-машины)

Карта сети: Tailscale-пиры, локальные адреса, шлюзы, Wi-Fi, публичные IP с
приблизительным регионом, uptime и состояние агента каждого узла. Для
выбранного узла: полная информация о железе, дисках, LM Studio, процессах;
кнопки `lms ps/ls/load/unload/server`, `nvidia-smi`, диски, файлы моделей,
запуск и остановка `llama-server`. Команда на естественном языке
переводится LLM в одно действие из белого списка и выполняется **только
после подтверждения**; журнал команд с выводом сохраняется в сессии.

Кто администратор: интерфейс, открытый на машине хаба (localhost или её
адрес), плюс IP из Настройки → Подключение → «Дополнительные IP».
Режим можно отключить (тогда администраторы — все).

## Подключение устройств и узлов (Админ → 🔗)

Секция «Подключение к платформе» на вкладке Админ:

* **Адрес для людей** — основной URL (имя Tailscale, на которое выписан
  сертификат), QR-код для телефона, другие адреса с пометкой, предупредит ли
  браузер, проверка условий (Tailscale, TLS, пароли), готовая инструкция для
  нового пользователя.
* **Подключить рабочий узел** — «Найти устройства» опрашивает все машины
  тейлнета (`POST /api/admin/discover`): агент на порту 8766, открытые порты
  LLM-серверов (1234/1235/8080/11434/8000) с моделями, уже добавленные узлы.
  Кнопки: «📡 Агент» (ключ + команда установки для этой машины), «➕ Узел
  :порт» (мастер добавления с подставленным адресом и автопроверкой).
* `POST /api/admin/connect` — адреса и состояние для этой секции.

QR-код генерируется на клиенте (`web/qr.js`, байтовый режим, уровень M,
версии 1–10; проверен декодером на всех версиях).

### Роль — только по паролю

При включённом входе по паролю IP хаба **не даёт** прав администратора:
ни установщика, ни админских маршрутов — только сессия с
ролью `admin`. IP хаба сохраняет лишь право первичной настройки
(`/api/auth/setup`) и `--reset-auth`. `POST /api/auth/login` принимает
`role: admin|user` — тогда проверяется пароль именно этой роли; без `role`
проверяются пароли обеих ролей.

## Пользователи

Имя задаётся самим пользователем; в списке подключений видны IP,
устройство и ОС (Client Hints), браузер, экран, язык, часовой пояс, число
ядер и памяти, тип соединения, а также сопоставление с пиром Tailscale
(имя устройства, ОС, прямой адрес). Ветки помечены владельцем, фильтр
«Мои / Все» в панели слева.

## Безопасность

Настраивается в Настройки → 🔒 Безопасность. Четыре слоя:

1. **Сетевой фильтр** — по умолчанию принимаются только приватные сети
   (Tailscale 100.64.0.0/10, LAN, localhost). Можно слушать только адрес
   Tailscale или только localhost (`security.bind`).
2. **Вход по паролю** — два пароля: администратора и пользователя. Хранятся
   как PBKDF2-SHA256 (240k итераций, своя соль). Сессии — отзываемые токены
   с ограниченным сроком; после 8 неудач IP блокируется на 15 минут.
   Пользователь не получает секретов в API, не меняет узлы и модели.
3. **Подпись команд узлам** — HMAC-SHA256 по телу запроса + метка времени +
   nonce. Подмена команды и повтор перехваченного запроса отклоняются;
   секрет по сети не передаётся. Кнопка «Проверить каналы к узлам» отдельно
   убеждается, что агент отвергает неподписанные команды.
4. **TLS** — кнопка «Получить сертификат Tailscale» выпускает настоящий
   сертификат на `hostname.tailXXXX.ts.net`; после перезапуска хаб на https.
   (Внутри Tailscale трафик и так шифруется WireGuard.)

Потерян пароль администратора: на хост-машине `python hub_server.py --reset-auth`.

## Датчики

Блок «🌡 Датчики» в телеметрии каждого узла: температура CPU и GPU, частота
CPU (максимальная, средняя и эффективная — по счётчику «% Processor
Performance»), частота каждого ядра, частота шины, частота и объём ОЗУ,
частоты ядра/видеопамяти/видеодвижка GPU, обороты и проценты кулеров,
потребление CPU/GPU/ОЗУ и итог по системе.

Источники: **nvidia-smi** (всё по GPU, без доп. ПО), счётчики Windows и WMI
(частоты, ОЗУ), **LibreHardwareMonitor** через WMI — нужен для температуры и
мощности CPU и оборотов корпусных кулеров; на Linux — hwmon/RAPL. Значения,
которые вычисляются, а не измеряются (мощность CPU без датчика, ОЗУ,
платформа), помечены как оценка; отсутствующие показываются как «н/д».

### Как читаются датчики GPU

Данные NVIDIA берутся напрямую из NVML (`nvml.dll` / `libnvidia-ml`) через
ctypes — это те же цифры, что у `nvidia-smi`, но за миллисекунды и без запуска
процесса. Поэтому частота, температура, мощность и загрузка GPU обновляются
каждую секунду независимо от медленного опроса WMI (он занимает 10–20 с и
отвечает за CPU, память и плату). Если NVML недоступен, агент откатывается на
`nvidia-smi`. В заголовке блока датчиков видно: «GPU: NVML».

Замечание по RTX 3060: в простое карта держит 1852 МГц / P0 и ~46 Вт, а не
210 МГц / P8 — её не отпускают Parsec (кодировщик) и загруженная модель в
LM Studio (Vulkan-контекст). Это реальное состояние, не ошибка телеметрии.

## Агент: endpoints

Хаб дополнительно раздаёт: `GET /node_agent.py` (исходник агента),
`GET /install-agent.ps1`, `GET /install-agent.sh` (установщики с адресом хаба внутри).

`GET /telemetry · /sensors · /sysinfo · /downloads · /actions · /speedtest?bytes=N`
`POST /upload · /exec {action,args} · /download {source} · /download/cancel {id}`

Управляющие endpoints (`/exec`, `/download`, `/sysinfo`) принимают запросы
только с приватных адресов и только с корректной подписью
(`X-BF-Sig` / `X-BF-Ts` / `X-BF-Nonce`) на секрете кластера; ключ
передаётся агенту при установке (`--secret`). Произвольные команды оболочки
не выполняются — только белый список `ACTIONS`.
